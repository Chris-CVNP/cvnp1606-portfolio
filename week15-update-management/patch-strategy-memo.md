Ring rationale
Ring 1 Pilot ring will receive quality updates when available from Microsoft. Ring 2 Standard ACME will wait 7 days before receiving quality updates. This way, if there is a Patch Tuesday update that results in a device being unable to boot, or a driver conflict, or breaks a business application; we see this occur on the pilot device first, giving us the opportunity to pause the production ring prior to any branch devices receiving the update.
Deferral value choices
Ring 1 Pilot ring utilizes a 0 day Quality deferment, and a 7 day Feature deferment. This means Ring 1 will validate quality updates as soon as they become available. Ring 2 Production ring utilizes a 7 day Quality deferment, and a 30 day Feature deferment. The 7-day Quality gap gives us a full week to monitor the pilot ring before offering the same update to branch devices. A 30 Day feature deferment provides additional time since feature updates typically have a larger impact on the Operating System. Our deadline for production ring updates is to complete quality updates within 3 Days after the deferral ends, with a 2 day grace, and feature updates within 14 Days after the deferral ends, also with a 2 day grace. Branch Devices average greater than 45 Days behind in regards to quality updates, so our goal was to create deadlines which force installations at the end of each deferment instead of allowing users to delay indefinitely.
Monitoring strategy
After the pilot ring receives an update I would access the Windows Quality Updates Report in the Intune Admin Center under Reports > Windows Updates. I would then verify how many pilot devices are reporting that the update has been Installed, Pending or Failed. In addition, I would also verify the Per Device Status for each failed device and obtain its Error Code. The Rollout will be deemed healthy only when all Pilot Devices report that the update is successfully Installed with zero failures before the Deferment for the Production Ring has ended.
Continuity and recovery proof
Rollback path: If pilot devices fail the update, or are otherwise impacted, pause quality updates on Ring 2 Production Standard so production devices do not receive the update. Use the Uninstall Action on Ring 1 Pilot to remove the most recent quality update. Once a fixed update is released, resume the rings.
Monitoring signal: Any pilot device reporting Failed for the Quality Update in the Windows Quality Updates Report, An error code in Per Device Windows Update Status for a failed device, Or User reports Boot Failure/ Application Failure after update completes Installation.
Escalation trigger: If any pilot device fails the update or cannot boot or run a business application after it installs, immediately stop roll out by Pausing Ring 2 Production Standard and contact Maya prior to end of deferment period for Ring 2 Production Standard. If failure persists after retry of Intune Sync, and Uninstallation; or matches Known Issue Microsoft has not resolved, open support case with Microsoft.
